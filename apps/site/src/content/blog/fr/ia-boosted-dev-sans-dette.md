Les assistants IA changent la vitesse à laquelle on écrit du code, mais pas automatiquement sa qualité. Voici les trois règles que j'applique pour garder les deux.

## 1. Toujours relire comme un reviewer, pas comme un auteur

Le code généré doit passer la même revue que le code écrit à la main : lisibilité, gestion des cas limites, cohérence avec l'architecture existante.

## 2. Garder les tests comme filet, pas comme option

Un assistant peut halluciner un comportement. Les tests automatisés restent la seule preuve fiable que le code fait ce qu'il doit faire.

## 3. Documenter les décisions, pas le code

Le code généré explique déjà *quoi*. Ce qui manque souvent, c'est le *pourquoi* — ce qui reste utile pour la prochaine personne (humaine ou IA) qui touchera ce fichier.
